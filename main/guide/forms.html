表單與錯誤提示 ​

這篇說明四件事：表單欄位怎麼包、驗證錯誤怎麼顯示、怎麼在選項清單尾端新增自訂項、Wizard 裡的 Enter 鍵怎麼運作。

做表單、或要接上驗證錯誤之前，先讀這篇。

先判斷 ​

你要做的事做法用什麼
欄位要有標題、必填標示外層包一層。標題只放欄位名稱；單位、限制、提示放 hint；必填把 required 設為 trueField
某個欄位驗證沒通過在欄位元件傳 errorMessage。有值就進入錯誤狀態，空字串就清除Input、Select、Date Picker 等，見下一節
按送出時條件還不足主按鈕維持停用外觀但可以點，點了說明原因並捲到第一個錯誤欄位Button 的 clickableWhenDisabled，見浮層怎麼選
在選項清單尾端新增自訂項觸發鈕原地變成輸入框，按 Enter 送出。不用 window.prompt，也不在 Modal 裡再疊 DialogInline Add
Wizard 或表單 Modal 裡按 Enter兩段式：第一次 Enter 把焦點移到主按鈕，第二次才真的送出下方規則「Wizard 鍵盤導航」

欄位錯誤訊息怎麼顯示 ​

錯誤訊息掛在欄位元件本身，不掛在 Field。Field 只管標題與必填標示。選填欄位不加任何標示。

共通的寫法：

  • errorMessage 是開關。有字就顯示錯誤，空字串就是沒有錯誤。
  • 錯誤提示是浮動的 tooltip，不佔版面。
  • errorPosition 決定提示在欄位上方（top）或下方（bottom），預設 bottom。
  • 欄位錯誤預設顯示在欄位下方，一般情況用預設值即可。只有版面放不下（例如欄位下方緊接著其他內容、會被遮住）時，才改成 errorPosition="top"。
元件錯誤相關屬性補充
InputerrorMessage、errorPosition
TextareaerrorMessage、errorPosition
Number InputerrorMessage、errorPosition
SelecterrorMessage、errorPosition
AutocompleteerrorMessage、errorPosition
Date PickererrorMessage、errorPosition
Button GrouperrorMessage、errorPosition只有 type="form" 有效
Inline Confirmerror、errorMessage、errorPositionerror 切換警示色框；errorMessage 預設顯示在勾選項下方
Upload DropzoneerrorMessage、errorPosition預設顯示在上傳區下方，框線同時轉成錯誤紅

在有明確送出按鈕的 Modal 或 Wizard 裡，使用者點了停用的主按鈕時，所有錯誤同時顯示，畫面捲到第一個錯誤欄位。這個流程寫在浮層怎麼選的底部按鈕段落。

情境與範例 ​

欄位驗證沒通過 ​

下面的範例還沒選日期時顯示錯誤。選好日期後，errorMessage 變成空字串，錯誤就消失。

html
<app-field label="出生日期" [required]="true">
  <app-date-picker
    mode="day"
    size="M"
    [errorMessage]="pickerValue ? '' : '請選擇出生日期'"
    [(ngModel)]="pickerValue">
  </app-date-picker>
</app-field>
text

在選項清單尾端新增自訂項 ​

點「＋ 新增其他項目」，按鈕會原地變成輸入框。輸入後按 Enter，新項目會加進清單並勾選。

  • 只有 Enter 會送出。內容去掉前後空白後不是空字串，才會發出 add 事件。
  • 按 Esc 或點到別處（blur）一律取消，輸入的內容丟掉。
  • 元件只負責輸入。去重、加入清單、勾選都在父層的 add 事件處理。
  • 新增後立刻勾選並送後端。失敗時怎麼處理，見載入與回饋。
html
<div class="chip-wrap">
  @for (opt of options(); track opt) {
    <app-check-chip [text]="opt" [(ngModel)]="checked[opt]"></app-check-chip>
  }
  <app-inline-add (add)="addCustom($event)"></app-inline-add>
</div>
text
尚無 Vue 版：#check-chip、#inline-add
ts
// 父層：去重 + 加入清單 + 勾選（資料留在父層）
addCustom(name: string) {
  if (this.options().includes(name)) return;
  this.options.update(l => [...l, name]);
  this.onToggle(name, true); // 自動勾選並送後端
}
text
尚無 Vue 版：#check-chip、#inline-add

Wizard 裡的 Enter 鍵 ​

Wizard 的 Enter 分兩段，避免使用者打完一格就誤觸換頁：

  • 焦點在文字欄位時按 Enter：焦點移到當頁的主按鈕（下一步、送出），不直接送出。
  • 焦點在主按鈕時再按 Enter：才真的送出。
  • 焦點在多行文字框（textarea）時，Enter 保留換行。
  • 輸入法正在選字時，Enter 是確認選字，不攔截。
Button Group 已內建對應的鍵盤行為：方向鍵在選項之間移動，Space 只切換選項。對未選中的選項按 Enter 會切換過去；對已選中的選項再按一次 Enter，事件會往外傳給 Wizard，由 Wizard 把焦點移到下一步按鈕。

下面的範例可以用方向鍵、Space、Enter 試試看。範例外層沒有 Wizard，所以對已選中的選項再按 Enter 不會有反應。

規則 ​

Inline 新增自訂項 form.inline-custom-add

原則：在既有選項清單（chip 群組 / tag 列）尾端讓使用者新增「自訂項」時，用 inline 輸入（觸發鈕原地變輸入框）而非 native window.prompt、也不在 modal 內疊 dialog。單行自由文字的新增應就地完成、不打斷流程；committed 後即生效（optimistic）。

什麼時候用：設計任何「預設選項 + 可新增自訂項」的多選 chip / tag / 清單尾端新增。對應元件：Inline Add。

情境說明規則
inlineCustomAddchip 群組尾端新增自訂 chip：點 ghost 觸發鈕 → 原地變 inline Input → Enter 提交成一顆已勾選 chip
為什麼：native prompt 不可樣式化、無法測、跨瀏覽器不一致；dialog 疊在多頁 modal 上是 modal-on-modal、打斷 wizard。inline 輸入延續「清單尾端就地新增」的慣例，單行文字最省力。
  • 使用 Inline Add 元件
  • 僅 Enter 提交（trim 後非空才 emit）；Esc / blur 一律取消丟棄（最不意外）
  • 元件只管「輸入 affordance」，不持有清單 / 勾選；去重、加入清單、勾選由父層的 add 事件 handler 處理（展示櫃原則）
  • committed 後自動勾選 + 立即送後端（對應 mutation.feedback.optimisticAtomic）
  • 輸入態 keydown stopPropagation，避免方向鍵被 chip 群組 roving focus（wizard.keyboard）攔截
  • reopen / 換頁回來：自訂項需由 read-path 併回渲染清單（後端回傳的非預設條目 union 進預設清單），否則 checked 但不渲染

不要這樣做

  • inlineCustomAdd 用 native window.prompt → 不可樣式化 / 無法 e2e 測 / 跨平台外觀不一
  • inlineCustomAdd 在已是 modal 的 surface 內再開 dialog 輸入單行文字 → modal-on-modal 過重
  • inlineCustomAdd 元件自己持有清單 / 勾選 → 違反展示櫃原則，父層無法控制去重與後端同步
  • inlineCustomAdd 新增後不自動勾選 → 使用者以為已生效，實際未送後端（混淆 + 漏存）
  • inlineCustomAdd reopen 只還原 checked 不併回清單 → 自訂 chip 不渲染（checked 卻看不到）

無障礙

  • 鍵盤：Enter 提交、Esc 取消；輸入態方向鍵留在輸入框內（不觸發 chip 群組 roving focus）；觸發鈕 → 進編輯態後焦點自動移入 input
  • 焦點：blur 離開輸入框 → 取消編輯態並還原為觸發鈕
  • ARIA：輸入框沿用 Input 標準語意；外層 chip 群組維持 role="group"

相關元件：Inline Add Check Chip Input 

Wizard 鍵盤導航 wizard.keyboard

原則：Wizard 的 Enter 鍵分兩段：第一次 Enter（焦點在表單欄位）→ 焦點跳到當頁主要 action 按鈕；第二次 Enter（焦點已在按鈕）→ 真正觸發動作。設計目的是避免誤觸直接換頁，同時讓鍵盤使用者不必離開鍵盤就能完成整個 wizard 流程。

什麼時候用：設計 wizard、多步驟表單 modal、或任何含「下一步 / 送出」最終 action button 的互動 surface 時。

情境說明規則
textInput焦點在 <input> 一般文字欄位
為什麼：符合使用者「打完這格就完成了」的心流預期；兩段式 Enter 保留誤觸緩衝
  • 按 Enter → preventDefault，焦點跳到當頁主要 action 按鈕（下一步 / 送出）
  • 若該按鈕 disabled → 不跳焦（或保持焦點不動）
buttonGroup焦點在 Button Group 的選項按鈕
為什麼：保留「用 Enter 切換選項」的鍵盤能力，同時讓「已確認選擇」的使用者能用第二次 Enter 離開 button-group；符合使用者「再按一次 Enter」的直覺語意
  • 第一次 Enter（選項未選中）→ preventDefault，切換為該選項
  • 第二次 Enter（焦點在已選中的選項）→ 不 preventDefault，事件冒泡給外層 wizard 的 onFormEnter，由 wizard 把焦點丟到下一步按鈕
  • Space 鍵一律只做「切換選項」，不冒泡（a11y 慣例：Space = 切換 control，Enter = 預設動作）
  • 方向鍵 ← → ↑ ↓ 仍僅在 button-group 內循環移動焦點
textarea焦點在 <textarea>
為什麼：多行文字欄位的 Enter 必須保留換行語意，Ctrl/Cmd+Enter 才是「完成」
  • Enter 保留原生換行，不冒泡、不觸發跳焦
actionButton焦點在非 button-group 的一般按鈕（如「新增聯絡窗口」、footer 取消鍵等）
為什麼：一般按鈕的 Enter = 按下該按鈕，不該被攔截到其他地方
  • Enter 保留原生 click 行為，不觸發跳焦
  • onFormEnter 往上找祖先元素（closest）判斷是否為 Button Group 的子按鈕
composingIME輸入法選字視窗開著（中文注音、日文假名等）
為什麼：IME composing 中按 Enter 若被攔截 → 選字不完成 + 焦點飛走 = 災難體驗
  • 一律不攔截 Enter（event.isComposing === true 或 keyCode === 229）
  • 使用者的 Enter 是選字確認，不是 submit
subModalOpenwizard 內開著更上層的 sub-modal（例如編輯 modal 內再開的 dialog）
為什麼：子 modal 的 Enter 由子 modal 自己處理；父層不應攔截
  • wizard 的 onFormEnter 檢查 sub-modal 開啟旗標 → 早退，避免跨層跳焦

不要這樣做

  • button-group 的 Enter 無條件 preventDefault → 使用者無法用 Enter 離開 button-group，必須鼠標 / Tab 輔助
  • onFormEnter 把所有 <button> 一律 skip → button-group 子按鈕永遠不冒泡
  • Enter 直接 click 下一步按鈕（不經過「焦點中繼站」）→ 誤觸率高，使用者無法取消
  • checkbox / radio 的 Enter 觸發 submit → 打破原生切換語意
  • 不檢查 event.isComposing → 中文輸入法使用者大量誤觸

無障礙

  • 鍵盤：Tab / Shift+Tab：正常進 / 出 wizard 各欄位；Enter：兩段式（欄位 → 按鈕 → 送出）；Space：在 button-group 上純切換，不觸發跳焦；← → ↑ ↓：僅在 roving tabindex 元件內移動焦點（button-group、radio-chip 等）；ESC：關閉 wizard（或叫出「要儲存嗎」二次確認，視 dismissal pattern）
  • 焦點：Wizard 開啟 → 焦點落在第一個 enabled input / select；切換步驟 → 焦點回到該步的第一個欄位；下一步按鈕 disabled 時 → 不把焦點丟上去，避免視覺「卡住」
  • ARIA：Button Group 使用 role="group" + aria-pressed；下一步 / 送出按鈕使用 type="button"（wizard 不靠原生 form submit）；目前有驗證錯誤時，錯誤訊息透過 aria-describedby 連結到欄位
