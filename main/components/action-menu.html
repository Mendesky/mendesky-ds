Action Menu ​

右鍵或 More 按鈕展開的浮層，有兩種用法。當選單用時，每一項都放 Menu Item。放了 Menu Item 才是選單：報讀軟體會念出「選單」和 ariaLabel 設的名稱，鍵盤與焦點也改照選單的規則走，規則寫在下面的無障礙說明。當篩選面板這類一般浮層用時，裡面放 Button、Check Chip、輸入框，鍵盤與焦點照一般浮層的規則走（見下方無障礙說明），不會被念成選單。兩種都不要自己手刻 <button>、<div> 當選項。

用法

app-action-menu（Angular 版 v0.6.0）

在範例網站看全部 4 個範例

程式碼範例

More 操作選單（autoCloseOnAction 預設 true）

<!-- 父層需 position:relative -->
<div class="plan-header__more">
  <app-icon-btn (btnClick)="isPlanMenuOpen.set(true)">
    <app-icon name="More" size="16"></app-icon>
  </app-icon-btn>

  @if (isPlanMenuOpen()) {
    <app-action-menu (closeMenu)="isPlanMenuOpen.set(false)">
      <app-button variant="ghost" color="danger" size="S"
        leftIcon="Trash-Del" text="刪除此規劃">
      </app-button>
    </app-action-menu>
  }
</div>

複雜篩選面板（autoCloseOnAction="false"）

<div class="filter-wrap">
  <button (click)="toggleFilter('kanban', $event)">看板</button>

  <app-action-menu *ngIf="activeFilter() === 'kanban'"
    style="min-width:220px"
    [autoCloseOnAction]="false"
    (closeMenu)="activeFilter.set(null)">
    <!-- 含勾選、輸入等互動元素 -->
    <app-check-chip *ngFor="let s of columns" ...></app-check-chip>
    <app-button variant="elevated" size="S" text="還原預設"></app-button>
  </app-action-menu>
</div>

Angular 注意事項

本體說明裡負責 anchor 追蹤與 z-index 遞增的「浮層定位服務」，在 Angular 是 PortalPositioningService；app-action-menu 內部用它做定位與 anchor 追蹤。

父層不需要額外寫 @HostListener 處理 click-outside：PortalPositioningService 在 document 上以 capture-phase pointerdown 偵測外部點擊，點到外部時 app-action-menu emit (closeMenu)。

z-index 的下限是 PortalPositioningService 裡的常數 Z_INDEX_FLOOR（9999），每開一個 portal +1。

無障礙

網頁和 APP 都要做到

鍵盤
  • 放了 Menu Item 的選單：上下方向鍵只在選單項目之間移動，停用的項目也停得到；在最後一項按下會回到第一項，在第一項按上會跳到最後一項。Home、End 分別跳到第一項、最後一項。
  • 放了 Menu Item 的選單：Enter 或空白鍵執行目前這一項。按住不放也只執行一次：放開之前的連發不會讓打開選單的按鈕再打開選單，也不會按到接著拿到焦點的按鈕（例如選的那一項打開的對話框裡的按鈕）。Esc 關閉選單，焦點回到打開選單的按鈕。Tab 也會關閉選單，焦點接著移到打開選單那顆按鈕的下一個元素。
  • 沒放 Menu Item 的浮層（篩選面板、選項還是 Button 的選單）：上下方向鍵在可以按的按鈕之間移動，焦點在輸入框裡時方向鍵照常移動游標；Enter 或空白鍵觸發目前這一項，按住不放也只觸發一次：用鍵盤快捷鍵打開浮層時按著沒放，連發不會按到浮層裡的第一項，放開之前的連發也不會按到接著拿到焦點的按鈕；Esc 關閉，焦點還給打開前有焦點的元素。Tab 不會關閉浮層，Home、End 也沒有特別的作用。
焦點
  • 沒放 Menu Item 的浮層，打開時焦點移到第一個可以按的項目。autoFocusFirst 設成 false 時不移，由呼叫端自己帶進去，例如錨點是輸入框、打開後還要繼續打字的時候。
  • 放了 Menu Item 的選單，打開時焦點停在 selected 為 true 的那一項；沒有選中項才停在第一項。autoFocusFirst 設成 false 時一樣不移，由呼叫端自己帶進去。
  • 放了 Menu Item 的選單，選完一項或點外面空白處關掉之後，焦點回到打開選單的按鈕。要是焦點已經被別的東西拿走，例如選的那一項打開了對話框，就不會把焦點搶回來。點外面時按到的是別的按鈕、連結、輸入框這類可以操作的元素，也當成使用者換去操作那個東西，焦點交給瀏覽器處理，不拉回打開選單的按鈕。選單是被這樣一個元素的動作關掉的也一樣，例如同一排工具列裡另一個選單的按鈕，打開它的時候把這個選單關掉；按的是打開這個選單的那顆按鈕本身時，焦點照樣回到它。點到對話框卡片這類外框裡的空白處，就算瀏覽器把焦點給了外框，也當成點空白處，焦點照樣還給打開選單的按鈕。按下去那一刻焦點本來就不在選單裡時也一樣不拉回，例如 autoFocusFirst 設成 false、焦點一直留在錨點的輸入框。打開選單的是輸入框時，點外面關掉一律不把焦點還給它：使用者是點走了，游標不該跳回輸入框，一拿到焦點就打開的下拉也不會被重新打開；按 Esc 關掉時照樣還。
  • 放了 Menu Item 的選單開著時，項目全被拿掉（例如清單重新載入後變成空的），外框就不再是選單、接不住焦點，焦點還給打開選單的按鈕。
  • 點外面關掉、把焦點還給打開選單的按鈕時，頁面不會跟著捲動，按鈕已經捲出畫面也不會被捲回來。Esc、Tab 或選完一項關掉時，頁面照常捲到看得到那顆按鈕，用鍵盤的人才知道焦點在哪。
  • 焦點要還給哪顆按鈕，先認跟選單放在同一個外層元素裡、aria-haspopup 是 menu 或 true，而且選單開著時標著 aria-expanded="true" 的那顆；打開對話框、清單的按鈕（aria-haspopup 是 dialog、listbox 等）不算。有另外指定錨點元素（anchorEl）時，改認錨點元素本身和它裡面，錨點元素本身就是這種按鈕時直接用它。同時有好幾顆標著 aria-expanded="true" 時（例如同一個外層裡另一個選單也開著），取打開前有焦點的那顆；打開前的焦點不在其中任何一顆上，就不從裡面挑。只有一顆標著、但打開前的焦點在外層裡別的地方時，也不認它：例如上一層的浮層一直開著，打開浮層的按鈕（aria-haspopup 是 menu）一直標著，這個選單是從浮層裡的元素打開的。焦點停在包著那顆標著的按鈕的外框上，不算別的地方：只開一個選單時，Safari 點觸發鈕，焦點會停在這種外框上（例如加了 tabindex="-1" 的 role="gridcell" 格子）。這一條要打開前的焦點落在打開選單的元素上才認得出來，也就是用 Chrome 滑鼠點、用鍵盤打開，或點的是 tabindex="0" 這類 Safari 也會給焦點的元素。Safari 用滑鼠點、iPhone 用手指點原生按鈕時，按鈕拿不到焦點，這一條認不出來，焦點可能跳到打開浮層的按鈕。所以打開選單的按鈕一定要照規格設 aria-expanded：設了就有兩顆標著，照前面好幾顆標著的規則挑，不會還到打開浮層的按鈕。這樣認出來的按鈕優先於打開選單前有焦點的元素：Safari 用滑鼠點按鈕時按鈕不會取得焦點，焦點會落到外面那層點得到焦點的元素（例如 tabindex="-1" 的對話框卡片），打開前有焦點的可能是那一層。認不出來時，才把焦點還給打開前有焦點的元素；Safari 用滑鼠點按鈕、打開前沒有元素有焦點時，焦點就不還。沒有一顆標著 aria-expanded="true" 時不猜，外層裡只有一顆 aria-haspopup 是 menu 的按鈕也一樣：用鍵盤快捷鍵、右鍵打開的選單，那顆按鈕可能跟它無關。用 Chrome 滑鼠點、或用鍵盤打開時，打開前焦點就在按鈕上，漏設 aria-expanded 看不出來，要用 Safari 滑鼠點來驗。
  • 放了 Menu Item 的選單，點到分隔線或空白處時不會關閉，焦點留在選單外框上，方向鍵照樣能用。外框接得住焦點，但不在 Tab 順序裡。
報讀軟體
  • 放了 Menu Item 的選單，報讀軟體會念出「選單」和它的名稱。名稱來自 ariaLabel，用畫面上看得到的字，例如「排序」「每頁顯示筆數」。
  • 沒放 Menu Item 的浮層不會被念成選單：外框沒有角色也沒有名稱，報讀軟體照裡面每個元件自己的角色念。
  • 打開選單的按鈕要讓報讀軟體知道它會打開選單、選單現在開著沒有。用 Button 或 Icon Button 當觸發鈕時，設 ariaHaspopup 和 ariaExpanded。

網頁專屬

ARIA 與 HTML 語意
  • 放了 Menu Item 時，外框是 role="menu"，ariaLabel 輸出成 aria-label，外框也加上 tabindex="-1"。沒放時這三個都不會出現。
  • 選單裡的分隔線要標 role="separator"。
  • 打開選單的按鈕標 aria-haspopup="menu"，再用 aria-expanded 跟著選單開關變。

注意事項

（2026-08-13 使用者拍板）卡片底色與邊框以實作為準：底色 rgba(255,255,255,0.45)（不是 0.72）、邊框用 --border/white 純白（不是 0.85 半透明）。已寫進上方視覺規格表，勿再視為漂移回報。

（2026-04 更新）元件自動 portal 到 document.body，父層不再需要 position:relative。使用 position:fixed 定位，解決 transform/overflow:hidden 容器裁切問題。anchor 追蹤由浮層定位服務以事件驅動完成（document capture-phase scroll、window resize、trigger 的 ResizeObserver、visualViewport 變化），非 rAF 輪詢；rAF 只用於 attach 後的單次初始定位與同帧節流。context-menu 模式（attachAtPoint）不追蹤捲動。

autoCloseOnAction=true（預設）：適合點選即執行的 More 操作選單，點任何選項後自動關閉。放了 Menu Item 的選單只有點到可以用的選項才關，點到分隔線、空白處或停用的選項都不會關。

autoCloseOnAction=false：適合含輸入欄、多選 chip、套用按鈕的複雜篩選面板，讓使用者操作完再手動關閉

不需要在父層自己偵測外部點擊：浮層定位服務以 capture-phase pointerdown 偵測，點到外部時元件送出 closeMenu 事件，父層接這個事件關閉選單
