Process Toast ​

非同步操作的回饋通知。提供 action 時顯示 undo 按鈕（reversibleToast pattern）。loading 型別搭配 toast 服務的 show({persist:true}) + update(id, patch) 可做「進行中→完成」單一 toast 原地轉場（如匯出 PDF：文件產生中→已開始下載）——update() 僅限這種「同一件事的兩個階段」，不同事件各自一顆、堆疊（例如逐欄存檔時，每一欄的存檔結果各自一顆，不要用 update() 互相取代）。渲染一律經全域 Toast Container 全域 Toast 容器（掛 app root），元件不自建本地 toast stack；唯一例外是使用端自己的全域 API 錯誤浮層（若有，自有 z-index 9999 層，需壓在 doc-preview 之上）。層級規則（2026-08-13 定案）：Toast Container 全域 Toast 容器 為 2100，必須壓過 doc-preview 與 template-var-panel 的 2000 層——否則檔案預覽開啟時的操作回饋會被蓋住看不到（先前為 1600，實際被 doc-preview 蓋住）；全域 API 錯誤浮層與 tooltip portal 維持 9999（API 錯誤與游標提示更優先）。duration 由型別決定、呼叫端不自帶：success/loading 3000ms、error 5000ms、有 action 5000ms。容器內 toast 預設 pointer-events: none，僅帶 action 者可點（toast 位於卡片右下角，無條件可點會吃掉數秒點擊）。文案長度：.toast__msg 的 line-clamp:2 約在 29 全形寬靜默截斷；各類型的字數上限（例如 success/loading 16 全形寬、error 24、有 action 18）由使用端自訂；插值長度必須有界。

用法

app-process-toast（Angular 版 v0.6.0）

屬性

名稱型別預設說明
type'success' | 'error' | 'loading''error'Toast 類型：success 綠勾 / error 紅 / loading 中性白底 + 旋轉 spinner（進行中）；決定背景色與 icon
messagestring''顯示訊息（單行）
durationnumber3000 / 5000自動消失毫秒數。caller 未指定時：有 action → 5000，沒 action → 3000
size'S' | 'M''S'尺寸：S 為預設輕量小尺寸（260×40px），M 為大尺寸（333×56px）
actionToastActionundefined選填的 undo 按鈕。提供時於右側顯示文字按鈕；按下呼叫 onClick（通常是呼叫還原 API）並關閉 toast；toast 自動消失代表使用者未反悔，不觸發 onClick
stackModebooleanfalsetrue 時改為 position:static、寬度填滿容器，位置交給所屬容器排版（app-toast-container 堆疊多顆時用，手機版只吃寬度與掉落動畫）；false 時自身 position:fixed 置中定位（單獨使用）
(dismissed)EventEmitter<void>退場動畫結束後觸發，用於從 DOM 移除元件
requestHidebooleanfalse設為 true 時從外部觸發離場動畫（ToastService 用它控制消失時機）

程式碼範例

介面定義

// 從 process-toast 元件 import
import { ToastAction } from '...process-toast/process-toast.component';

interface ToastAction {
  label: string;              // 按鈕文字，例：'復原'
  onClick: () => void;        // 通常呼叫還原 / undelete API
}

配合 @if 控制顯示（M，預設）

@if (showToast) {
  <app-process-toast
    type="success"
    message="項目已成功建立"
    [duration]="3000"
    (dismissed)="showToast = false"
  ></app-process-toast>
}

S 小尺寸（輕量通知）

@if (showToast) {
  <app-process-toast
    type="success"
    message="已儲存"
    size="S"
    [duration]="2000"
    (dismissed)="showToast = false"
  ></app-process-toast>
}

含復原（reversibleToast pattern）

@if (showToast) {
  <app-process-toast
    type="success"
    message="已刪除「附件 A」"
    [action]="{ label: '復原', onClick: restoreAttachment }"
    (dismissed)="showToast = false"
  ></app-process-toast>
}

// component.ts
restoreAttachment = () => {
  // 呼叫還原 API（動作已寫入，不是 pending queue）
  this.attachmentService.restore(this.lastDeletedId).subscribe();
};

Angular 注意事項

本體說的「toast 服務」在 Angular 是 ToastService：以 inject(ToastService) 取得；loading 型別呼叫 show({ persist: true }) 後，再用 update(id, patch) 原地轉場。

注意事項

（2026-08-13 使用者拍板）位置以實作為準：bottom 為 calc(24px + var(--dock/h, 48px) + 16px)、right 為 24px。原文件的固定 32px 會讓 toast 壓在底部工具列上；動態值在工具列高度變化時自動跟隨。

undo 語意：使用者操作當下 API 已經成功寫入，toast 自動消失不代表「提交」，只是 UX 計時結束；onClick 的職責是呼叫還原 / undelete API。詳見 ds-patterns.js 的 action.confirm-destructive → reversibleToast。

防重點：actionFired 一次性旗標擋下重複觸發；toast 被外部 dismiss 或元件 destroy 時清除 timer。
