本頁內容

Command Palette ​

從一大批資料裡找出一筆並開啟它：按一個按鈕或快速鍵，跳出一個對話框，上面是搜尋框，下面是結果，打字、用上下鍵選、按 Enter 就開。資料很少、一眼看得完時不需要它。列表上方跟著字篩選的搜尋框用 Search Field；從清單選一個值填進表單欄位用 Autocomplete。

部位

  1. 對話框：搜尋樣式的 Modal Shell：靠畫面上方，預設寬 680 px，最高到畫面高度的 72%。平板以下的螢幕，寬度由 Modal Shell 改成幾乎佔滿畫面，兩邊各留 8 到 12 px。
  2. 搜尋列：對話框樣式的 Search Field，固定在最上面。右邊留了一個位置給頁面放按鈕，例如「搜尋」。
  3. 說明位置：在搜尋列和清單之間，放頁面自己的一行說明。沒放就不佔空間。
  4. 結果清單：Result List。結果超過對話框高度時，只有這一塊會捲，搜尋列和按鍵提示不動。
  5. 按鍵提示：固定在最下面，靠右排三組：↑ ↓ 瀏覽、↵ 選取、esc 關閉。「選取」兩個字可以換成選了之後會發生的事，例如「開啟」。可以整列關掉。

狀態

狀態長怎樣、什麼時候出現
關著畫面上沒有任何東西。
打開對話框從上方滑進來，焦點在搜尋框，馬上可以打字。
清單的狀態平常、載入中、沒有結果、載入失敗四種，畫法跟 Result List 一樣，由頁面指定。
觸控裝置沒有鍵盤，按鍵提示不顯示。其他都一樣，用點的選。

可以這樣做、不要這樣做

✅ 可以這樣做

  • 對話框的名稱寫清楚在找什麼。「搜尋項目」比「搜尋」好懂。
  • 提示文字寫可以打什麼來找，例如「輸入名稱或編號」。
  • 開啟一筆要等後端時，自己擋住重複觸發。使用者連按兩下 Enter，元件會通知兩次。
  • 收到「字變成空的」時，把結果一起清掉，或換回還沒打字時的內容（例如最近開啟）。

❌ 不要這樣做

  • 不要自己用 Modal Shell、Search Field 再組一個。鍵盤、焦點、報讀的接線有十幾處，每組一次就會漏幾處。
  • 不要把一定要讓使用者知道的事只寫在按鍵提示裡。觸控裝置上看不到，報讀軟體也不念。
  • 不要在結果列裡放按鈕或連結。整列已經是一個選項，要對某一筆做別的事，選了它之後再提供。
  • 不要拿它當表單用。它只有一個搜尋框和一份結果，要填好幾個欄位用一般的對話框。

無障礙

網頁和 APP 都要做到

鍵盤
  • 焦點在搜尋框時：↓、↑ 在結果裡移動選中，焦點不離開搜尋框。
  • 有選中的列時按 Enter，選取那一列。沒有選中時按 Enter，元件通知頁面「送出查詢」並帶上目前的字，由頁面決定要做什麼，例如只有一筆結果時直接開。這兩種 Enter 都不會再傳到頁面。同時按著 Ctrl、⌘ 或 Alt 的 Enter 不算，元件不處理，也不攔。
  • 框裡有字時按 Esc，第一下只清空，對話框不關，這一下也不會傳到頁面。框裡沒字時按 Esc，元件通知頁面想關；這一下是 Modal Shell 在整頁的層級接的，頁面上其他聽整頁按鍵的地方也收得到。
  • 用輸入法選字時按的 ↓、↑、Enter、Esc 是給輸入法的，元件不處理。按住 Enter 不放只算第一下。
  • 焦點在清除鈕或右邊的按鈕上時，↓、↑、Enter 不會去動清單：在按鈕上按 Enter 就是按那顆按鈕。
  • 焦點在清除鈕上按 Esc，跟在搜尋框裡一樣是清空，焦點回到搜尋框。焦點在右邊的按鈕上按 Esc，會直接通知頁面想關，有字也一樣。
  • Tab 在對話框裡繞：搜尋框、清除鈕（有字才有）、右邊的按鈕、載入失敗時的重試鈕。結果列用 Tab 停不到，要用上下鍵選；結果多到要捲動時，捲動的那一塊也不是 Tab 停點。
焦點
  • 一打開，焦點就在搜尋框，不用等進場動畫跑完，所以打開後馬上打的字不會漏掉。
  • 關掉、退場動畫跑完之後，焦點回到打開前的那個元素，通常是打開它的按鈕。如果這段時間使用者已經把焦點移到別的元素上，就不搶回來。
  • 頁面不用、也不要自己在打開或關閉時放焦點。
  • 按了載入失敗的重試鈕之後，焦點回到搜尋框。重試鈕接著會消失，焦點不放回去會掉出對話框。
  • 關掉後退場動畫還沒跑完就重開，元件記得最早那個元素，下一次關掉還是把焦點還給它。
報讀軟體
  • 對話框一定要有名稱，寫它在找什麼，例如「搜尋項目」。搜尋框預設用同一個名稱，也可以另外給。
  • 搜尋框會告訴報讀軟體：它控制下面那個清單、清單現在有沒有列可以選、目前選到哪一列。
  • 載入中、找到幾筆、找不到、載入失敗，由 Result List 的報讀區念出來。
  • 按鍵提示只是畫面上的提醒，報讀軟體不念。
動態
  • 進場和退場各約 0.45 秒，是 Modal Shell 的動畫。
觸控
  • 觸控裝置上不顯示按鍵提示。判斷方式是「沒有滑過、指標是粗的」，接了鍵盤的平板也不會顯示。

網頁專屬

ARIA 與 HTML 語意
  • 對話框是 role="dialog"、aria-modal="true"，名稱用 aria-label。
  • 搜尋框是 role="combobox"，aria-controls 指到清單，aria-autocomplete="list"；aria-expanded 在清單有列可以選時是 true；aria-activedescendant 指到選中那一列，沒選中時沒有這個屬性。
  • 按鍵提示整列是 aria-hidden="true"。

注意事項

它是三個元件組起來的：搜尋樣式的 Modal Shell、對話框樣式的 Search Field、Result List，最下面再加一列按鍵提示。鍵盤、焦點和報讀的接線都已經做好，頁面只要給資料。

元件不打後端，也不決定搜什麼。字變了它通知頁面，頁面去查，再把結果和狀態（平常、載入中、沒有結果、載入失敗）交回來。要等使用者停下來才查，由頁面自己做。

開關由頁面管。使用者按 Esc 或點背景時，元件只通知「想關」，並說是哪一種；選了一列之後元件也不會自己關，因為開啟那一筆可能要等後端，要不要先關由頁面決定。

還沒打字時可以先放東西，例如一組「最近開啟」。它跟搜尋結果是同一種清單，一樣可以用上下鍵選。清單上面也可以放一行頁面自己的說明，例如可以搜尋的範圍。

關掉時，元件會把框裡的字清空、把選中清掉，並通知頁面字變成空的。重新打開不會看到上一次的字和結果。退場動畫那段時間焦點還在搜尋框，但這時打的字、按的鍵元件都不再理會。

用哪個快速鍵打開由頁面決定，元件不聽全站的按鍵。⌘K（Windows 是 Ctrl+K）是瀏覽器願意讓網頁接的；⌘N、⌘T、⌘W 這些接不到，不要用。
