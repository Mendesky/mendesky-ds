Result List ​

使用者在輸入框打字，下面列出結果，用上下鍵選一列、按 Enter 開啟：搜尋結果、最近開啟、建議清單都是這種。焦點一直留在輸入框，使用者可以邊選邊繼續打字。整個搜尋對話框已經組好的版本是 Command Palette；只要這塊清單、輸入框自己放時才直接用它。要從清單選一個值填進表單欄位，用 Autocomplete。

部位

  1. 清單：所有列的外框，四周留 8 px。沒有列可以畫、或狀態不是平常時，清單藏起來，位置讓給狀態區。
  2. 群組標題：12 px 的字，顏色跟列的名稱一樣，在那一組的第一列上面。沒給標題的群組沒有這一塊。
  3. 列：一筆結果。高度至少 32 px，上下 8 px、左右 12 px 的留白，圓角 4 px；列與列隔 2 px。
  4. 列的內容：預設是圖示（16 px，有給才有）、名稱（14 px）、說明（12 px，有給才有）。頁面給了自己的列內容時，這一塊整個換掉。
  5. 狀態區：載入中是轉圈加一行字；沒有結果是放大鏡圖示加一行字；載入失敗是紅色圖示、標題、說明和重試鈕。
  6. 報讀區：畫面上看不到。載入中、有幾筆結果、找不到、載入失敗，都從這裡念給報讀軟體使用者聽。

狀態

狀態長怎樣、什麼時候出現
平常照頁面給的群組把列畫出來。
選中用鍵盤移到、或滑鼠移到的那一列（滑鼠要真的動了才算：用鍵盤讓清單捲動時，停著不動的滑鼠不會把選中搶走），底色變成淺灰，再加一圈跟焦點框同色的藍色外框，字的顏色不變。只靠淺灰底跟白底差太少，看不出選到哪一列，所以要有外框。同一時間只有一列是選中。在 Windows 高對比這類強制色彩模式下，底色會被系統拿掉，外框改用系統醒目色。
按下滑鼠按著某一列時，底色再深一階。
載入中清單藏起來，改顯示轉圈和「搜尋中」。這時上下鍵和 Enter 都沒有作用。
沒有結果顯示放大鏡圖示和一行字，預設是「找不到結果」，頁面可以換成帶關鍵字的句子。
載入失敗顯示標題和說明。頁面有接「重試」時才出現重試鈕；不能重試的地方不會多一顆按了沒用的按鈕。

可以這樣做、不要這樣做

✅ 可以這樣做

  • 使用者按了重試，就把焦點放回輸入框。重試鈕接著會消失，不放回去的話鍵盤使用者要重新找焦點。
  • 查詢的字一變，就請元件把選中還原。不然使用者打完新的字馬上按 Enter，可能開到上一批結果裡選中的那一筆。
  • 只列出前幾筆時，自己寫報讀的句子，把「總共找到幾筆」說出來。畫面上只看得到 20 列，不代表只找到 20 筆。
  • 「沒有結果」的句子帶上使用者打的字，例如「找不到『甲』的相關結果」，使用者比較容易發現是自己打錯。

❌ 不要這樣做

  • 不要把清除鈕或旁邊按鈕上的按鍵也轉給元件。在那些按鈕上按 Enter 是要按那顆按鈕，轉進來會變成選取清單裡的列。
  • 不要拿它當選單用。選單打開後焦點要進到選單裡，用 Action Menu。
  • 不要在自己的列內容裡放按鈕、連結這類可以點的東西。整列已經是一個選項，裡面再放一個可以點的，鍵盤使用者按不到它。
  • 不要給重複的項目識別碼。畫得出來，但選中只認第一筆，後面同一個識別碼的列用鍵盤選不到，上下鍵也走不過去。

無障礙

網頁和 APP 都要做到

鍵盤
  • 按鍵是在輸入框上按的，由頁面轉給元件。按 ↓ 選下一列、按 ↑ 選上一列，會跨群組。
  • 預設到最後一列再按 ↓ 不動；在第一列按 ↑ 回到沒選中。開了「繞回」之後，頭尾會接起來。
  • 有選中的列時按 Enter，選取那一列。沒有選中時元件不處理 Enter，交給頁面決定要做什麼。
  • 元件用掉的 ↓、↑、Enter 不會再往外傳，也不會移動輸入框裡的文字游標。按住 Enter 不放只選一次。
  • 用輸入法選字時按的 ↓、↑、Enter 是給輸入法的，元件不處理。同時按著 Alt、Ctrl 或 ⌘ 的也不處理。
  • Home、End 留給輸入框移動文字游標，不拿來跳到第一列或最後一列。
焦點
  • 焦點不會進到清單裡，一直留在輸入框。用滑鼠在列上按下去也不會把焦點帶走，點完可以接著打字。
  • 清單裡的列用 Tab 停不到。要讓鍵盤使用者選得到，輸入框的按鍵一定要轉給元件。
  • 元件自己不捲動，由頁面放進會捲動的區塊裡。內容超出高度時，Chrome 和 Firefox 會把會捲動的區塊變成一個沒有名稱的 Tab 停點。頁面要把那個區塊設成 Tab 停不到，並在它被滑鼠點到、拿到焦點時把焦點放回輸入框。
  • 按了重試之後，重試鈕通常跟著消失（狀態換成載入中），焦點會掉到頁面上，上下鍵和打字都失效。頁面要在重試時把焦點放回輸入框。
報讀軟體
  • 清單一定要有名稱，例如「搜尋結果」。
  • 選到哪一列，是透過輸入框告訴報讀軟體的：輸入框指著清單，並標出目前選中那一列。這件事要頁面把元件送出來的「選中那一列的 id」接到輸入框上才成立；Search Field 有對應的設定。
  • 狀態改變時會念一句：載入中念「搜尋中」，有結果念「找到 N 筆」，沒有結果、載入失敗念畫面上那句話。只列出一部分結果時，頁面可以自己寫要念的句子，例如「找到 54 筆，先列出前 20 筆」。
  • 載入失敗時，失敗訊息有些報讀軟體可能念兩次：元件念一次，裡面的 Empty State 錯誤版本自己也標了要念。
動態
  • 選中的底色有 0.15 秒的過渡。使用者在系統裡開了「減少動態」，就直接換色。

網頁專屬

ARIA 與 HTML 語意
  • 清單是 role="listbox"，有 id 和 aria-label。每一列是 role="option"，各有不重複的 id；選中的那一列 aria-selected="true"，其他是 false。
  • 有標題的群組是 role="group"，用 aria-labelledby 指到標題；標題本身是 role="presentation"。
  • 報讀區是 role="status"，從一開始就在畫面上而且是空的，之後才填字。
  • 載入中的轉圈和畫面上那行字不重複念：轉圈是裝飾，那行字標成 aria-hidden="true"。

注意事項

元件只負責畫清單和記住選到哪一列。它不打後端、不管輸入框：要列什麼、現在是不是在載入，都由頁面告訴它；輸入框上的按鍵也由頁面轉給它。

內容用「群組」給。群組有標題就畫成有標題的一組，例如「最近開啟」；沒有標題就直接把列排出來。上下鍵會跨群組一路往下走，標題不會被選到。

每一列預設顯示圖示、名稱和一行說明。要放別的東西（例如前面一個編號標籤），頁面可以給自己的列內容，元件只留列的外形、選中的樣式和點擊。

選中是用項目自己的識別碼記的，不是記第幾列。結果換了一批之後，原本選中的那一筆還在就繼續選著它，不在了就變回沒選中。查詢的字改了、或面板關掉時，頁面要請元件把選中還原，不然下一批結果裡剛好有同一筆時，使用者一按 Enter 就會開到它。

預設一開始不選任何一列，按 ↓ 才從第一列開始，到最後一列就停住。這樣使用者剛打開、什麼都還沒做就按 Enter，不會誤開第一筆。想要「一有結果就選好第一列」或「到底繞回第一列」，各有一個開關。開了「一有結果就選好第一列」之後，選中會跟著第一列：結果換了就選新的第一列，直到使用者自己用上下鍵或滑鼠移到別列為止；把選中還原之後又會跟著第一列。

元件自己不捲動。把它放進有固定高度、可以捲的容器裡；用鍵盤選到看不見的列時，那一列會自己捲進來。
